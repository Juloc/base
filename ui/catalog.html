How to use the kit

Three files in the head, nothing to build (CODE-06). The app sets its colour with one variable in its own stylesheet (COLOR-01) and builds its pages from the parts below. Everything is served under /base/ by the base itself.

<script src="/base/boot.js"></script>
<link rel="stylesheet" href="/base/base.css">
<link rel="stylesheet" href="/app.css">        /* :root { --accent-hue: 152; } */
<script type="module" src="/app.js"></script>

// app.js
import { h, icon, api, shell, router, toast, openDialog } from '/base/base.js';
import { t, addMessages } from '/base/i18n.js';
import { start } from '/base/auth.js';      // setup assistant and sign-in, then your app

Button

One primary button per view. The label says what happens ("Delete entry", not "OK"). A finger needs 44 px (MOBILE-01); the height comes from --control-h.

A link as a button

Field

Every control has a visible label (FORM-01). A hint below explains, the error replaces guessing (FORM-02). In JavaScript: field({ label, name, hint }), passwordField().

Lower-case letters, digits, dot, dash and underscore.

The password needs at least 12 characters.

Switch, checkbox, segmented choice

A switch applies at once; a checkbox waits for "Save". Two to four options side by side: the segmented choice.

Card

Groups what belongs together. .card.flush has no padding, for a list or a table that runs edge to edge.

Appearance

List

Rows of at least 56 px: a lead, a title, one line below, an end. A whole row may be a link. Lists come in pages (LIST-01) and say something useful when empty (LIST-02).

Badge and notice

A badge marks a state in a word. A notice is a message that stays in the page; colour is never the only signal, there is always an icon or a word (A11Y-01).

Neutral Accent Done Waiting Failed

Toast

A short confirmation that goes away by itself. Never the only place for something the person must not miss; that is a notice.

Dialog

A window that does not block the page: it can be moved by its title, the page behind stays usable; on a phone it is a sheet from below (DIALOG-01). Escape closes it and the focus returns (DIALOG-01). Before something that cannot be undone, ask, and name the action on the button (DIALOG-01).

Menu

A few actions at a button. Arrow keys move, Escape closes.

Form with errors

submit(form, fn) makes the button busy and shows what the server refused at the field it belongs to; the first wrong field gets the focus (FORM-02). Send it empty to see.

People and the central sign-in

For the settings page of the role admin: peopleCard(me) of people.js (the list, an invitation link per new person, change the role, block, delete) and hubCard(me) of hub.js (address, client id, secret, on or off, check the connection). roleName(me, key) gives the name of a role as the app named it. The sign-in page of auth.js shows the button of the centre below its own form, and the invitation page (#invite=...) takes a new person through password and authenticator.

Shell

The frame of every app (SHELL-01): on a phone a head and a bar of up to five places at the bottom, thought of first (MOBILE-02); on a wide screen the menu on the left. The person menu (settings, light or dark, sign out) is the same everywhere (SHELL-01). Open the app to see it live.

Icons

One file, one style (KIT-01): icon('name') in JavaScript, <span data-icon="name"> in markup. An icon alone on a button needs an aria-label (A11Y-01).
